# account-access Specification

## Purpose

Обеспечивает доступ к личным данным владельца с Android и macOS и позволяет независимо управлять сессией на каждом устройстве.

## Requirements

### Requirement: Вход единственного владельца
Система SHALL предоставлять вход по учётным данным заранее созданного владельца и SHALL отклонять неверные данные без раскрытия существования учётной записи. Публичная регистрация SHALL отсутствовать.

#### Scenario: Успешный вход
- **WHEN** владелец вводит действительные учётные данные на Android или macOS
- **THEN** приложение открывает защищённую часть и получает доступ только к данным владельца

#### Scenario: Неверные данные
- **WHEN** введены неверные учётные данные
- **THEN** приложение остаётся на экране входа и показывает ошибку без доступа к личным данным

### Requirement: Независимые сессии устройств
Система SHALL сохранять действующую сессию после перезапуска приложения и SHALL позволять владельцу завершить сессию текущего устройства, не завершая сессию другого устройства.

#### Scenario: Повторное открытие приложения
- **WHEN** приложение открывается повторно с действующей сессией
- **THEN** владелец попадает в защищённую часть без повторного ввода учётных данных

#### Scenario: Выход на одном устройстве
- **WHEN** владелец выходит из приложения на Android
- **THEN** Android запрашивает вход при следующем обращении к защищённым данным, а сессия macOS остаётся действующей

### Requirement: Защита личного API
Система SHALL отклонять запросы к личным данным без действующей сессии.

#### Scenario: Запрос без сессии
- **WHEN** клиент обращается к данным профиля без действующей сессии
- **THEN** API возвращает отказ в доступе и не раскрывает содержимое профиля
